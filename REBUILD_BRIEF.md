## 4. Why it currently reads "basic" — diagnosis

Evidence-based, from reading the code:

1. **It is the generic 2025–26 "premium dev portfolio" template look:** near-black
   navy canvas (`#05070D`/`#080D18`) + simultaneous **blue + violet + cyan +
   magenta** glows + faint grid lines + glass panels + mono uppercase metadata +
   a "System Status" panel + `clip-path` masked text reveals. Every one of those
   is now a recognisable cliché. Put together, they read as generated, not
   authored.
2. **Low visual density.** The reference screenshot (1536×1024) measures
   **average brightness ≈ 27/255 (~10%)** and average RGB ≈ (21, 26, 44): a very
   dark, mostly empty frame with small bright text clusters and one modest
   brighter blob. On a normal phone/laptop screen this reads as *flat black*.
3. **Effects are tuned so low they nearly vanish.** Nebula bands at 6–16%
   opacity, orbit ring at `opacity-[0.16]`, grid masks, grain at 0.14. Individually
   tasteful; collectively invisible → the page has no focal contrast.
4. **One uniform rhythm across all 14 sections.** `Section` is always
   `border-t border-line` + `py-[clamp(2.5rem,6vw,5.5rem)]`, and nearly every
   section opens with the same `SectionHeading` (mono `index` + `eyebrow` +
   expanding rule + `text-h2` title). Same recipe 14 times = monotonous.
5. **One uniform card language.** `rounded-card` + `border-line` +
   `bg-surface-strong` + hairline ring + mono labels + split rows. Used for the
   status panel, identity sheet, design statement, metrics strip, etc.
6. **Mono is overused.** `.type-mono` (uppercase, `letter-spacing .16em`) is on
   labels, metrics, nav, rail, status, tags, annotations. Heavy mono is a
   "tech-template" tell.
7. **Template tells to audit/remove or justify:** "System Status" panel, "LIVE"
   badge + pulsing dot, `Fig. 01 — Portrait` + corner ticks + `2023 — 2027`
   annotations, `⌘K` command palette, custom cursor, scrolling marquees,
   "Scroll" cue.
8. **Copy is generic.** "Building digital products that solve real problems",
   "A CSE student turned product builder, focused on creating meaningful digital
   experiences." True but interchangeable with any bootcamp portfolio.

## 6. Pick ONE direction (then commit hard)

The current build is "dark sci-fi tech". If that is not the taste, choose a
different, **coherent** direction — don't keep adding glows to it.

**A. Editorial / Swiss-print (recommended if "basic" means *needs taste*).**
High-contrast, light-first (paper `#F5F3EE` / ink `#0B0B0C`), one accent.
Massive display type, generous whitespace, strict baseline grid, real
photography full-bleed, almost no glow/grain. Feels like a design studio, not a
dev template.

**B. Warm cinematic (if dark must stay).**
Deep charcoal (not navy), **one** warm accent (ember/amber), film-grain and
light, photographic portraits as the dominant visual. Drop blue+violet+cyan
entirely — the multi-hue glow is the single biggest "AI template" signal.

**C. Refined Midnight System (lowest-risk).**
Keep the owner-specified palette but **subtract**: one accent instead of four,
2–3× more contrast, larger type, varied section backgrounds (some lighter
panels), real photos dominant, remove the clichés in §4.7.

Whatever you pick, the page must have **one clear focal idea per screen.**

## 7. Concrete "premium" levers (apply after choosing a direction)

**Composition / density**
- Break the uniform stack: alternating column ratios, full-bleed media bands,
  offset/overlapping elements, occasional inverted (light) panels, sticky
  media + scrolling copy, at least 2–3 sections that are *not* a card grid.
- Give the page a clear rhythm: quiet → loud → quiet.

**Typography**
- Increase scale contrast: section titles can be far larger; body can stay
  small/quiet. Use Bricolage's width/optical axes deliberately.
- Cut `.type-mono` usage by ~half. Reserve mono for genuine data/code only.
- Consider a serif or a second display face for editorial contrast (check
  licence + `next/font`).

**Imagery**
- Make real photos the hero of the page. Replace the space composite. Show the
  **product videos** (`unimate-demo.mp4`, `fixbondhu-demo.mp4`) in tasteful,
  large frames with real UI, not mockups.
- One strong image beats four faint gradients.

**Colour**
- One accent, used with intent. If blue stays, remove violet+cyan+magenta.

**Motion**
- Fewer, slower, more deliberate. One signature moment (e.g., a real
  page/hero transition) beats 15 subtle ones. Keep the reduced-motion system.

**Texture**
- Reduce grain/grid/glow noise; earn contrast with layout and imagery instead.

**Copy**
- Rewrite hero + About statements with **specifics** (what was built, for whom,
  what changed). Specificity reads premium; generic adjectives read basic.

**Subtract the clichés** listed in §4.7 unless you can strongly justify each.

## 9. Gotchas the next model should know

- **SSR streaming transient:** immediately after load, sections can report
  `height: 0` / `docH ≈ 845` during `document.readyState === "loading"`. It
  self-heals at `complete` (~2.5 s). **Wait for `readyState === "complete"` and
  `scrollHeight > 5000` before measuring** — otherwise "no overflow" checks pass
  against an empty shell.
- **Measuring viewports:** the harness browser window is fixed (~1000px). To get
  true 320/390/1440 rendering, inject fixed-width **iframes** (same origin) and
  measure inside; wait for each iframe's `readyState === "complete"`.
- **Screenshots >16 MP fail** — use `maxWidth` or capture per-section.
- **Binary assets:** `core.autocrlf=true`; `.gitattributes` marks
  PDF/images/video/fonts binary. Verify committed blobs are byte-exact.
- **`resume.pdf`** is generated by `npm run resume:build`; `resume_url` unset so
  the committed file is used.
- **Deploy:** Vercel CLI authed; `VERCEL_OIDC_TOKEN` in `.env.local` (no
  `VERCEL_TOKEN`).
